## 3. 実測で判明した仕組み（再実施者向け）

- **「OCR」列とは別に、AI構造化抽出が「入力1」としてカウントされる**。OCR（生読取）と入力1（構造化）が一致した項目は**人間ゼロで自動確定**する（会社名・役職名・郵便番号・住所1・電話・携帯・FAX・URLで観測）。G6 URLはこれにより人間入力なしで0件化
- 照合画面の列構成: 項目名称/OCR/DB/入力1/入力2/入力3/修正入力/完成内容/確定。青行=確定済み・赤行=未確定
- **空入力の確定は「入力」として記録されない**（Lv1がG2を空のまま確定→照合画面に痕跡なし・実害なし）
- **照合キューは要対応レコード（不一致等）のみを提示**する。一致済みレコードは照合画面での個別保存が不要（STG-SCN-035の「全レコードを確定→保存」記述と挙動が異なる）
- 保存時の確認は `#modal-overlay` のモーダル（×/OK）。作業画面のボタンは `#confirm-button`（確定 Ctrl+Enter）/`#skip-button`/`#suspend-button`（作業終了）
- 名刺入力の入力欄はグループごとにラベル+input（例: G1 `#email`、G2 `#lastname`/`#firstname`）
- 管理ログインはユーザー側 `/login` と別の **`/admin/login`**（`name=userid`/`name=password`）
