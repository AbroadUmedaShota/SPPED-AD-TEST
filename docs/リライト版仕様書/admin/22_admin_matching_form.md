# 照合個票・照合画面 要件定義書

| 項目 | 値 |

| owner | product |

## 1. 文書目的

- 本書は、名刺 1 件ごとの照合を行う作業画面の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 照合対象アンケートの一覧と進捗管理は本書の対象外とし、`21_admin_matching_list.md` で扱う。

## 2. 画面概要

- OCR 結果と複数オペレーターの入力結果を項目ごとに見比べ、正しいデータを決める作業画面。
- 一致・不一致を識別表示し、不一致の項目にのみ修正入力を行う。
- データの最終決定は管理者（Lv2 以上）が行う。入力作業者の入力結果は候補であり、確定値ではない。
- 1 件あたりの判断回数が多いため、キーボードのみで一連の操作を完結できる構成とする。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 照合作業を行う Lv2（OperatorAdmin）。本画面の主たる利用者。
- 運営全体を管理する Lv3・Lv4。全グループの名刺を照合できる。

### 3.2 対象範囲

- 名刺画像（表裏同時表示）と画像操作
- 項目ごとの値の並列表示
- 一致・不一致の識別表示
- 不一致項目への修正入力と確定
- 照合中の排他制御（照合ロック）

### 3.3 対象外

- 照合対象アンケートの一覧・進捗・完成データの取得（`21_admin_matching_list.md`）
- 名刺データの入力作業（`20_admin_data_input_form.md`）
- 例外名刺の処理（エスカレーション画面 SCR-A-016 は検討凍結中）

## 4. 画面要件

### 4.1 共通構成

- 誤操作を防ぐためサイドバーは表示しない（`01_admin_common_ui.md` §2）。主要領域は縦スクロールなしで 1 画面に収める。離脱の導線は「一覧へ戻る」ボタンとする。
- 画面は上下 2 領域で構成する。上段に名刺画像（表・裏の横並び）、下段に項目の比較表を全幅で配置する。比較表は列数が多く、左右分割では長い値が折り返すため。
- 画面上部に、対象が属するアンケートのアンケート ID とタイトル、納期日時を表示する。

### 4.2 名刺画像の表示と操作

- 名刺の表と裏の画像を同時に表示する。上段の領域内に横並びで配置する。
- 画像に対して拡大、縮小、回転の操作を提供する。
- 画像はマウスオーバーでカーソル位置を起点に拡大表示し、クリックでその位置・倍率のまま固定できる（再クリックで解除）。拡大率は 1.0 倍から 4.0 倍の範囲を 0.5 刻みで調整し、初期値を 2.0 倍とする。入力画面（SCR-A-010）§4.2 と同じ操作体系とする。
- 画像操作はキーボードからも実行できるようにする。

### 4.3 項目の並列表示

各項目について、次の値を横に並べて表示する。

| 列 | 内容 |
| --- | --- |
| OCR 結果 | 名刺画像から機械的に読み取った値 |
| DB 値 | 既存データベースに保持している値（値の由来は §11 で確定） |
| 入力 1 | オペレーター 1 名目の入力値 |
| 入力 2 | オペレーター 2 名目の入力値 |
| 入力 3 | オペレーター 3 名目の入力値 |
| 修正入力 | 照合担当が入力する値 |
| 完成内容 | 確定後に採用される値 |

- 項目は 1 行 1 項目として縦に並べ、列の並び順は上表のとおりとする。
- 値が存在しない列は「—」を表示する（`01_admin_common_ui.md` §9）。

### 4.4 一致・不一致の識別表示

- 各項目の状態を行単位で識別表示する。状態は「一致」「不一致（修正対象）」「不一致（確定済み）」の 3 つとする。不一致の行には項目名の横に不一致である旨を併記する。
- 状態の対応を示す凡例を比較表の近くに置く。
- 一致した項目は、一致した値をそのまま完成内容に採用する。
- 不一致の項目は、修正入力の対象として区別して表示する。修正入力に値が入った時点で「不一致（確定済み）」へ移り、完成内容にその値を表示する。値を消すと「不一致（修正対象）」へ戻る。
- 一致・不一致の判定条件は §11 で確定する。

### 4.5 修正入力と確定

- 不一致の項目に対して、照合担当が正しい値を入力する。入力した値を完成内容に採用する。
- 名刺から読み取れない箇所には「〓」を入力する。文字単位で用いる（`20_admin_data_input_form.md` §4.4）。
- 全項目の完成内容が決まった状態で確定操作を行い、次の対象へ進む。決まっていない項目が残っている間は確定操作を非活性とし、残件数を画面下部に表示する。
- 確定操作の実行時は確認ダイアログを表示し、完成内容で確定する旨を明示する。
- 修正入力欄の移動と確定はキーボード操作で実行できる。`Enter` は次の未確定の修正入力欄へ移動し、すべて確定済みであれば確定の操作へ移動する。
- 画面上部にショートカット一覧を開く導線を置く。一覧は `?` からも開閉できる。

### 4.6 照合ロック

- 照合を開始した名刺はロックし、他の担当が同時に照合できない状態とする。
- 一定時間操作がない場合、ロックを自動解除して他の担当が照合できる状態へ戻す。
- ロック中に画面を離れた場合も、自動解除の時間経過をもってロックを解放する。

参考: 現行画面のロックは約 200 秒で自動解除される。正式な解除時間は §11 で確定する。

### 4.7 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| 候補値のクリック選択 | OCR 結果・入力 1〜3 の値を押下し、修正入力欄へ反映する。既に値が入っていた場合は上書きしたことが分かるように示し、直前の値へ戻せるようにする |

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない |
| Lv2 | 自グループの名刺のみを照合できる |
| Lv3 | 全グループの名刺を照合できる |
| Lv4 | 全グループの名刺を照合できる |

- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- 完成内容の決定はこの権限範囲でのみ行える。入力作業者（Lv1）は完成内容を決定しない。

## 7. 状態と挙動

### 7.1 初期表示

- 照合管理一覧から遷移した時点で、対象アンケートの照合対象を 1 件表示する。
- 不一致の項目が存在する場合、最初の不一致項目の修正入力欄にフォーカスを置く。
- 表示と同時に対象名刺をロックする。

### 7.2 確定後の遷移

- 確定すると完成内容を保存し、ロックを解放して次の対象を同一画面に表示する。
- 対象が残っていない場合は、その旨を表示し照合管理一覧へ戻る導線を提供する。

### 7.3 ロックの競合

- 他の担当がロック中の名刺は出題しない。
- 出題できる名刺が 1 件もない場合、その旨を表示し、対象を再取得する操作と照合管理一覧へ戻る導線を表示する。未照合の名刺がすべて他の担当のロック中である場合も、この状態に含める。
- 自身のロックが自動解除された後に確定操作を行った場合、確定を受け付けず、対象が解放された旨を表示する。
- このとき入力済みの修正入力は破棄しない。画面上に保持したまま、対象を再取得して再度確定できる状態とする。作業 1 件あたりの入力量が多く、破棄すると同じ判断をやり直すことになるため。実現方式は §11 で確定する。

### 7.4 照合の中断

- 修正入力の途中で画面を離れる場合、入力内容がある間は確認ダイアログを表示する（`01_admin_common_ui.md` §8）。
- 確定していない修正入力は保存しない。

### 7.5 応答時間

- 確定操作から次の名刺が表示されるまでの時間は 1 秒以内を目標とする（`05_admin_nonfunctional.md` §2）。

## 8. 現行画面からの引き継ぎ

現行画面（照合管理一覧から遷移）は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 項目ごとの値の見比べ | §4.3 |
| 修正入力 | §4.5 |
| 照合ロック（約 200 秒で自動解除） | §4.6 |
| 行ごとの確定チェック | 引き継がない（下記） |

現行画面は比較表の右端に行ごとの確定チェックの列を持ち、ヘッダーに全選択のチェックを備える。チェックを入れるとその行の修正入力が読み取り専用になり、外すと再び編集できる。値が一致した行は初期状態でチェック済みとして表示される。

本書はこの列を引き継がない。判断の根拠は次のとおり。

- 一致した行が初期状態でチェック済みで表示されるため、チェックの有無は担当者が内容を確認したかどうかを表さない。確認の証跡としては機能しない。
- 現行画面の保存操作はチェックの状態を参照していない。チェックを入れずに保存でき、保存の可否を制御していない。
- 完成内容の決定は、一致した項目はその値をそのまま採用し、不一致の項目は修正入力の値を採用する規則（§4.4、§4.5）で確定する。あわせて、全項目の完成内容が決まるまで確定操作を非活性とする（§4.5）ため、チェックの記入漏れよりも確実な歯止めが働く。
- 誤って確定済みの値を書き換えることへの対処は、確定操作時の確認ダイアログ（§4.5）で行う。

ただし、担当者が確定チェックを「どの行まで見たか」の目印として運用している可能性は現行のコードからは判断できない。そうした運用が実在する場合は本判断を見直す。

参考: 現行モック `03_admin/reconciliation/detail.html` の比較表は §4.3 の 8 列（項目／OCR 結果／DB 値／入力 1／入力 2／入力 3／修正入力／完成内容）で構成され、本書の内容と同期している。項目は `20_admin_data_input_form.md` §4.4 の作業グループ①〜⑧の全 16 項目を並べ、行の項目名にはどの作業グループに属するかを併記する。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] サイドバーが表示されず、主要領域が縦スクロールなしで 1 画面に収まる
- [ ] 画面上部に対象が属するアンケートのアンケート ID とタイトル、納期日時が表示される
- [ ] 表と裏の名刺画像が上段に横並びで同時に表示される
- [ ] 画像の拡大・縮小・回転がキーボードから実行できる
- [ ] 画像のホバー拡大とクリックによる固定・解除が実行できる
- [ ] 各項目について OCR 結果・DB 値・入力 1〜3・修正入力・完成内容が横に並んで表示される
- [ ] 値が存在しない列に「—」が表示される
- [ ] 一致・不一致（修正対象）・不一致（確定済み）の 3 状態が行単位で識別でき、凡例が表示される
- [ ] 一致した項目の値が完成内容に採用された状態で表示される
- [ ] 不一致の項目へ修正入力し、その値が完成内容に採用される
- [ ] 完成内容が決まっていない項目が残っている間、確定操作が非活性になる
- [ ] 初期表示で最初の不一致項目の修正入力欄にフォーカスが当たる
- [ ] 修正入力欄の移動と確定がキーボードのみで完結する
- [ ] 対象が残っていない場合、その旨と照合管理一覧へ戻る導線が表示される
- [ ] 出題できる名刺が 1 件もない場合（全件が他の担当のロック中である場合を含む）、その旨と再取得の操作、照合管理一覧へ戻る導線が表示される
- [ ] 修正入力の途中で画面を離れようとした場合に確認ダイアログが表示される
- [ ] ロックが解除された後の確定試行で、入力内容が失われず対象が解放された旨が表示される
- [ ] Lv2 でログインした場合、他グループの名刺が出題されない
- [ ] Lv1 でログインした場合、本画面へアクセスできない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | DB 値の由来 | 並列表示する「DB 値」が何を指すかを確定する。過去に確定した同一人物のデータか、回答時に取得した値かで、照合時の扱いが変わる。 |
| 2 | 一致・不一致の判定条件 | 何をもって一致とみなすかを確定する。入力 1〜3 の全一致か、多数決か、OCR 結果を含めるかで不一致件数が変わる。入力の確定条件（`20_admin_data_input_form.md` §11 の #2）、照合管理一覧の完了件数（`21_admin_matching_list.md` §11 の #5）、実績管理の正答率の分母（`24_admin_achievements.md` §11 の #1・#2）と併せて、本項を含む 4 点を同一の定義で確定する。定義が割れると、同じ作業に対して画面ごとに異なる件数が表示される。 |
| 3 | 入力が 3 件に満たない場合 | 入力 1〜3 のうち一部しか存在しない状態で照合対象となるかを確定する。 |
| 4 | ロックの自動解除時間 | 現行の約 200 秒を正式値とするかを確定する。作業 1 件あたりの所要時間を基準に判断する。 |
| 5 | ロック解除後の入力保持の実現方式 | §7.3 で定めた「入力内容を破棄しない」挙動をどう実現するかを確定する。画面側で保持して再取得後に再適用するか、下書きとして保存しておくかを決める。解除中に他の担当が同じ名刺を確定した場合、保持していた入力をどう扱うかも併せて決める。 |
| 6 | エスカレーション導線の扱い | 判断できない名刺の引き渡し先を確定する。エスカレーション画面が凍結中のため、当面の受け皿を決める必要がある。 |
| 7 | 確定の取り消し | 確定した完成内容を後から修正できるかを確定する。修正を許す場合、監査ログの記録対象に加えるかを併せて決める。 |
| 8 | キーボード操作の割当 | 確定、修正入力欄の移動、画像操作、候補値の選択に割り当てるキーを確定する。入力画面（SCR-A-010）と操作体系を揃える。現行モックの暫定割当は Ctrl+Enter=確定して次へ（確認ダイアログ表示中はそのまま実行）、Enter=次の未確定の修正入力へ（すべて確定済みなら確定の操作へ）、Alt+1〜3=フォーカス中の行の入力 1〜3 を修正入力へ複写（※暫定割当）、Ctrl+Z=複写を直前の値に戻す、+/−=拡大率（入力中は Alt 併用）、R=回転（入力中は Alt+R）、?=ショートカット一覧。 |
| 9 | 完成内容と完成データの関係 | 本画面で確定した完成内容が、照合管理一覧の完成データダウンロードへ反映されるタイミングを確定する。完成データの自動反映は開発側へ現状の開示を要求中である。`13_admin_survey_management.md` §11 の #5、`21_admin_matching_list.md` §11 の #11 と同一の論点であり、3 点を同時に確定する。 |
| 10 | 顧客データのグループ割り当て基準 | Lv2 が照合できる名刺の範囲は、顧客側データ（アンケート・回答・名刺）をオペレーターのグループへ割り当てる基準に依存する。基準は `00_admin_common_permissions.md` §10 の #10 で確定する。 |
