## 1. 文書目的

- 本書は、請求書管理（アカウントと発行月の組み合わせで作成する月次請求書の管理）の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- アンケート単位の請求と入金状況の管理は本書の対象外とし、`15_admin_billing.md` で扱う。
- 本書は請求管理とは別画面とする前提で記述する。1 本化の判断は §11 で扱う。

## 2. 画面概要

- アカウントと発行月の組み合わせで作成する月次請求書を一覧で確認する画面。
- 請求書 1 通ごとの内訳（月額利用料、お礼メール送信費用、請求合計）を確認する。
- 現行画面は一覧データが表示されない状態にあり、本書は画面単位の整理として要件を定義する（§8）。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 運営全体を管理する Lv3・Lv4。月次の請求書の内容確認と、顧客への提示・送付の判断を行う。

### 3.2 対象範囲

- 月次請求書の一覧・検索
- 請求内訳の確認

### 3.3 対象外

- アンケート単位の請求金額の補正と入金状況の管理（`15_admin_billing.md`）
- クーポンの発行・適用（`17_admin_coupon.md`）
- 請求書の顧客側での表示（利用者向け画面で扱う）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくず、フッターを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、検索条件、請求書一覧の順に配置する。

### 4.2 一覧表示

各請求書について次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| 発行月 | 請求書の発行対象月 |
| 会社名 | 請求先の会社 |
| 月額利用料 | 契約に基づく定額分（プレミアムプラン 月額 10,000 円・税別） |
| お礼メール送信費用 | お礼メール送信数に対する従量分（1 通 1 円・無料 100 件を控除） |
| 請求合計 | 上記を合算した金額 |

- 1 行が 1 通の請求書（アカウントと発行月の組み合わせ）に対応する。
- 金額は 3 桁ごとのカンマ区切りで表示し、単位を「円」とする（`01_admin_common_ui.md` §9）。
- 一覧はページングと表示件数の選択に対応する（`01_admin_common_ui.md` §4.3）。
- 各列で昇順・降順の並び替えができる。

### 4.3 検索

| 条件 | 種別 | 内容 |
| --- | --- | --- |
| 会社名 | 検索 | 部分一致で対象を絞り込む |
| 発行月 | 検索 | 年月を指定して絞り込む |

条件をまとめて初期状態へ戻す操作を用意する。

### 4.4 請求内訳の確認

- 一覧から対象を選択すると、請求書 1 通の内訳を表示する。
- 内訳には月額利用料、お礼メール送信費用、請求合計を表示する。
- 対象期間に発生したアンケート単位の請求との対応は §11 で確定する。

### 4.5 検討中の要件

| 要件 | 内容 |
| --- | --- |
| 請求書の出力 | 請求書を書面の形式で出力する。出力形式と記載項目は §11 で確定する |

## 5. 通知

本画面の操作を起点とする通知・メールの発火はない（`03_admin_common_notifications.md` §2）。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv3 | 全範囲の請求書を表示できる |
| Lv4 | 全範囲の請求書を表示できる |

- 本画面は金銭情報を扱うため、Lv2 以下はテナント分離により到達しない（`00_admin_common_permissions.md` §3）。
- 権限判定はサーバー側で行う（`00_admin_common_permissions.md` §9.1）。

## 7. 状態と挙動

### 7.1 初期表示

- 検索条件は未入力の状態で表示する。
- 一覧の既定の並び順は請求月の降順とし、直近の請求月を先頭に表示する。
- 表示件数の既定は 10 件とする。

### 7.2 該当が 0 件の場合

- 一覧の位置に該当なしの旨を表示する。

### 7.3 金額の再計算

- 請求管理（SCR-A-006）でアンケート単位の請求金額を補正した場合、対応する月次請求書の合計へ反映する。反映の契機は §11 で確定する。

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/invoice` は検索欄と一覧の列は表示されるが、一覧データがエラーで表示されない状態である（2026-07-23 および 2026-07-24 の両日で同一の状態を確認）。動作する機能を裏取りできていないため、引き継ぎの最低線は列構成と検索に限る。

| 現行の要素 | 本書での扱い |
| --- | --- |
| 一覧の列構成 | §4.2 |
| 会社名・請求月による検索 | §4.3 |

一覧の表示不良そのものは本書の対象外とし、実装時に解消する。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] 一覧に発行月・会社名・月額利用料・お礼メール送信費用・請求合計が表示される
- [ ] 金額が 3 桁ごとのカンマ区切りで表示され、単位が「円」である
- [ ] 会社名と発行月による検索が機能する
- [ ] 一覧から対象を選択すると請求内訳が表示される
- [ ] 請求合計が月額利用料とお礼メール送信費用の合算として表示される
- [ ] 初期表示の並び順が発行月の降順である
- [ ] 該当が 0 件のとき、一覧の位置に該当なしの旨が表示される
- [ ] Lv2 以下でログインした場合、本画面の URL へ直接アクセスしても表示されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 請求書とアンケートの単位関係 | 請求がアンケート単位で発生するのに対し、請求書はアカウントと発行月の組み合わせで作成される。1 通の請求書へ複数アンケートの請求を束ねるか、対応関係をどう保持するかを確定する。`15_admin_billing.md` §11 の #1 と同一の論点である。 |
| 2 | 請求管理との 1 本化 | 請求管理と 1 画面に統合するか、別画面のまま運用するかを確定する。統合する場合、本書を `15_admin_billing.md` へ統合する。 |
| 3 | 画面 ID の採番 | 別画面として存続する場合の画面 ID を採番する。 |
| 4 | 請求内訳の項目 | 月額利用料とお礼メール送信費用の 2 項目で足りるかを確定する。名刺データ化の従量分を内訳として持つかを含めて決める。消費税を内訳の行として持つか、請求合計に含めた税込表示とするか、税抜と税込を並記するかを併せて決める。`15_admin_billing.md` §11 の #3（請求金額の算出式・消費税の扱い）と同一の論点であり、2 点を同時に確定する。 |
| 5 | 請求書の確定タイミング | 月次請求書をいつ確定するかを確定する。確定後にアンケート単位の請求を補正した場合の再計算の扱いを併せて決める。 |
| 6 | 請求書の出力形式 | §4.5 を導入する場合、出力形式（PDF 等）と記載項目、押印・適格請求書の要件を確定する。 |
| 7 | 顧客側の請求書表示との整合 | 利用者向け画面で表示する請求書と、本画面で扱う請求書が同一のデータかを確定する。 |
| 8 | 現行の表示不良の原因 | 一覧データが表示されない原因を開発側へ確認する。データ不備か実装不具合かで、移行時の対応が変わる。 |
