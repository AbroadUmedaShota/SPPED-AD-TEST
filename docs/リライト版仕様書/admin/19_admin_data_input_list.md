# 名刺入力一覧 要件定義書

| 項目 | 値 |

| 対象画面 | `/admin/data_input_list` |
| 画面 ID | SCR-A-009 |

| owner | product |

## 1. 文書目的

- 本書は、名刺入力一覧の要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 名刺 1 件ごとの入力操作は本書の対象外とし、`20_admin_data_input_form.md` で扱う。

## 2. 画面概要

- 名刺データの入力作業を開始する入口となる画面。
- 作業グループ①〜⑧の単位で進捗と件数を表示し、どの作業グループが遅れているかを把握する。
- ログイン中のアカウントが着手できる作業可能件数を表示し、そこから入力画面へ遷移する。
- 表示範囲はログイン中アカウントのデータ範囲に従う（§6）。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 入力作業を行う Lv1（Operator）。自分が着手できる件数を確認し、入力画面へ入る。
- 作業を管理する Lv2（OperatorAdmin）。自グループの作業グループ①〜⑧の進捗を見て、遅れの有無を判断する。
- 運営全体を管理する Lv3・Lv4。全グループの入力状況を確認する。

### 3.2 対象範囲

- 作業グループ①〜⑧単位の進捗・件数の表示
- アカウントごとの作業可能件数の表示
- 入力画面（SCR-A-010）への遷移

### 3.3 対象外

- 名刺 1 件ごとの入力操作（`20_admin_data_input_form.md`）
- 照合作業の進捗管理（`21_admin_matching_list.md`）
- オペレーターの作業件数・正答率の集計（`24_admin_achievements.md`）
- 例外名刺の処理（エスカレーション画面 SCR-A-016 は検討凍結中）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくず、フッターを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- 画面は上から、作業可能件数、作業グループ①〜⑧の進捗の順に配置する。

### 4.2 作業可能件数

- ログイン中のアカウントが現在着手できる名刺の件数を数値で表示する。
- 作業可能件数は入力対象の全体キューから算出する。特定のアンケートに閉じた件数ではない。
- 件数が 0 件の場合、入力画面への遷移操作を非活性とする。

作業可能件数の算出定義は §11 で確定する。同一名刺に対する複数オペレーターの入力状況、および他のオペレーターが作業中の名刺を件数に含めるかによって値が変わる。

### 4.3 作業グループ①〜⑧の進捗

作業グループ①〜⑧のそれぞれについて次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| 作業グループ番号 | ① から ⑧ の識別 |
| 総件数 | その作業グループの項目を入力する対象名刺の件数 |
| 入力済み件数 | その作業グループの項目の入力が完了した件数 |
| 未入力件数 | その作業グループの項目の入力が完了していない件数 |
| 進捗 | 「入力済み件数 / 総件数」と百分率 |

- 件数は 3 桁ごとのカンマ区切りで表示する（`01_admin_common_ui.md` §9）。
- 集計対象はログイン中アカウントのデータ範囲に限定する。
- 集計の最終更新日時を併せて表示する。

作業グループ①〜⑧は名刺データ化の入力項目をまとめた単位である（①メールアドレス、②姓・名、③会社名・部署名・役職名、④郵便番号・住所、⑤電話番号、⑥ URL、⑦その他メモ、⑧フリー入力）。各グループの項目構成は `20_admin_data_input_form.md` §4.4 の項目表に従う。1 枚の名刺は複数の作業グループを通過して入力されるため、同一の名刺が複数の作業グループの総件数に計上される。

作業グループは会社・法人単位のグループとは別の概念である（`04_admin_common_glossary.md` §2）。

### 4.4 入力画面への遷移

- 作業グループごとに入力画面（SCR-A-010）への遷移操作を配置する。
- 作業可能件数の領域には、作業グループ①から入力を開始する操作を併せて置く。作業グループを選ばずに着手する場合の入口とする。
- 遷移操作の活性・非活性は次の順で判定する。作業可能件数（§4.2）が 0 件の場合、すべての作業グループの遷移操作を非活性とする。作業可能件数が 1 件以上の場合、対象件数が 0 件の作業グループのみを非活性とする。
- 遷移後の出題順は `20_admin_data_input_form.md` §4.3 に従う。
- 作業グループの選択が入力対象の項目を絞り込むか、進捗表示の単位に留まるかは §11 の #9 で確定する。前者であれば選択した作業グループの項目だけを入力する画面となり、後者であれば入力画面は `20_admin_data_input_form.md` §4.4 の全項目を扱う。モックアップは前者で作成しており、入力画面は選択した作業グループの項目のみを扱う（`20_admin_data_input_form.md` §4.1）。

### 4.5 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| グループ一括入力画面への導線 | 複数の作業グループをまたいで連続入力する画面への遷移を Lv2 以上に提供する |
| 多言語名刺の言語選択入力 | 入力対象の言語を選択して入力画面へ入る。選択肢は言語マスタの登録内容から表示する（`01_admin_common_ui.md` §8）。既定は「自動」とし、ログイン中アカウントの対応可能言語（`23_admin_operator_management.md` §4.2）の範囲で出題する。言語判定の実装内容は開発側へ開示を要求中であり、本項の導入可否は開示内容を受けて確定する（§11 の #5） |

### 4.6 検討中の要件

| 要件 | 内容 |
| --- | --- |
| 作業の割り振り直し | 遅れている作業グループの担当を変更する。確定時に割当通知が発火する（§5） |
| 遅れている作業の検知 | 納期に対して進捗が不足している作業グループを一覧上で識別できるようにする。判定条件は未定 |

## 5. 通知

- 作業の割り振り・割り振り直しを確定したとき、割り当て先のオペレーターへ割当通知を送信する（`03_admin_common_notifications.md` §2 の #6）。
- 通知には対象の作業グループと作業期限を含める。
- 割り振り操作は §4.6 で検討中の要件であり、通知の導入時期は割り振り操作の導入と連動する。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 自グループの作業のみを表示・操作できる |
| Lv2 | 自グループの作業のみを表示・操作できる。作業グループ①〜⑧の進捗を確認する |
| Lv3 | 全グループの作業を表示・操作できる |
| Lv4 | 全グループの作業を表示・操作できる |

- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- グループ一括入力画面への導線は Lv2 以上に表示する（§4.5）。

## 7. 状態と挙動

### 7.1 初期表示

- 作業可能件数と作業グループ①〜⑧の進捗を取得して表示する。
- 作業グループは番号の昇順で並べる。

### 7.2 作業可能件数の変動

- 作業可能件数は全体キューを対象に算出するため、他のオペレーターの作業進行によって変動する。
- 入力画面でスキップした名刺は全体キューに戻る。ただし 3 回スキップされた名刺は出題対象から除外し、キューへ戻さない（`20_admin_data_input_form.md` §4.5）。この動作は同一アンケート内に閉じず、他のアンケートの出題にも影響する。
- 画面を再表示した時点の値で件数を更新する。

### 7.3 集計値の反映

- 進捗と件数は最大 5 分の反映遅延を許容する（`05_admin_nonfunctional.md` §2）。
- 画面には集計の最終更新日時を表示する。

### 7.4 入力画面からの復帰

- 入力画面から戻った場合、作業可能件数と進捗を再取得して表示する。

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/data_input_list` は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 作業グループ 1〜8 のカード表示 | §4.3。表示項目を進捗・件数まで拡張する |
| 作業可能件数の表示 | §4.2 |
| 入力画面への遷移（0 件は非活性） | §4.4 |

参考: 現行モック `03_admin/data-entry/index.html` は「タスク名／進捗／最終更新日時」の一覧と個人実績詳細への導線を持ち、現行画面のカード構成とは異なる。モックは仕様上の正解とは扱わない。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] 作業グループ①〜⑧のそれぞれについて、総件数・入力済み件数・未入力件数・進捗が表示される
- [ ] 進捗が「入力済み件数 / 総件数」と百分率で表示される
- [ ] 件数が 3 桁ごとのカンマ区切りで表示される
- [ ] ログイン中アカウントの作業可能件数が表示される
- [ ] 作業可能件数が 0 件のとき、すべての作業グループの遷移操作が非活性になる
- [ ] 対象件数が 0 件の作業グループの遷移操作が非活性になる
- [ ] 集計の最終更新日時が表示される
- [ ] 入力画面から戻った際に作業可能件数と進捗が再取得される
- [ ] Lv1・Lv2 でログインした場合、他グループの名刺が作業グループの件数・進捗のいずれにも含まれない
- [ ] Lv2 以上でログインした場合にのみ、グループ一括入力画面への導線が表示される（§4.5 導入時）

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 作業可能件数の算出定義 | 全体キューのうち何を作業可能とみなすかを確定する。他オペレーターが作業中の名刺、既に自分が入力した名刺、スキップ済みの名刺の扱いを含めて決める。営業日カレンダー管理のアサイン（`18_admin_calendar.md` §7.3）が算出に影響するか、すなわちアサインされた日付・オペレーターの組み合わせで件数が変わるかを併せて決める。`18_admin_calendar.md` §11 の #9 と連動する。 |
| 2 | 名刺のオペレーターへの割り当て基準 | 出題キューの名刺をどの基準でオペレーターへ割り当てるかを確定する。アンケート単位か、受付順か、言語単位かで作業可能件数と進捗の見え方が変わる。作業グループ①〜⑧は入力項目の単位（§4.3）であり、本項の割り当て基準とは別の論点である。#1 の作業可能件数の算出定義と併せて決める。 |
| 3 | 割り振り直しの導入 | §4.6 の割り振り直しを導入するかを確定する。画面方針と割当通知の発火は割り振り操作の存在を前提としており、たたき台の検討中区分と食い違う。 |
| 4 | 遅れの判定条件 | 遅れている作業を検知する場合、納期までの残時間と未入力件数のどの関係を遅れとみなすかを確定する。 |
| 5 | 多言語名刺の言語判定 | 名刺の言語判定と振り分けは開発側の独自実装であり、現在その内容の開示を要求中である。判定結果を画面上で上書きできるようにするかは、開示内容を受けて確定する。 |
| 6 | 既定言語の保持先 | §4.5 は「自動」の参照先をオペレーターの対応可能言語とする。名刺そのものの言語を利用者・アンケートのいずれかに持たせる必要があるかを確定する。持たせる場合は保持先の画面へ項目を追加する。`12_admin_user_detail.md` §11 の #8 と連動する。 |
| 7 | グループ一括入力画面 | 一括入力画面を新規画面とするか、入力画面のモードとするかを確定する。 |
| 8 | 全体件数の表示 | Lv2 以上に対して、自グループを超えた全体件数を表示するかを確定する。 |
| 9 | 作業グループ選択の作用 | §4.4 の作業グループの選択が、入力画面で扱う項目を選択した作業グループへ絞り込むか、進捗表示の単位に留まるかを確定する。#1 の作業可能件数の算出定義と同時に決める。 |
| 10 | 顧客データのグループ割り当て基準 | Lv1・Lv2 に表示する作業グループと件数の範囲は、顧客側データ（アンケート・回答・名刺）をオペレーターのグループへ割り当てる基準に依存する。基準は `00_admin_common_permissions.md` §10 の #10 で確定する。 |
