# 管理者画面 非機能要件（共通編）

本書はモックアップ工程の対象外とする。本番化時に再定義する参考資料として扱う。

| 項目 | 値 |
| --- | --- |
| 対象 | 管理者画面 全画面 |
| 正本区分 | 参考資料。本番化工程で再定義する |
| owner | product |
| last_reviewed | 2026-07-31 |

## 1. 文書目的

- 本書は、管理者画面の性能、可用性、セキュリティ、運用保守、対応環境の要件を定義する。
- 旧資料 `docs/アーカイブ/旧要件定義書_20250521/00.要件定義書.txt` の第 4 章「非機能要件」を引き継ぎ、管理者画面の利用実態に合わせて記述し直したものである。
- 数値目標が旧資料で空欄のまま残っていた項目は、確定前として §8 に分離する。
- インフラ構成の詳細、サーバー構成図は本書の対象外とする。

## 2. 性能

| 対象 | 目標 |
| --- | --- |
| 通常時の画面表示 | 3 秒以内 |
| 一覧の検索・絞り込み・並び替え | 3 秒以内 |
| 名刺入力画面・名刺情報照合の次データ表示 | 1 秒以内 |
| CSV・名刺画像のダウンロード | データ量に応じた現実的な時間内。10 秒を超える場合は処理中であることを画面に表示する（目標値は※要確定・§8） |
| 集計値の反映 | 最大 5 分の遅延を許容する（準リアルタイム） |

- オペレーター実績確認、ダッシュボード、照合結果一覧の集計値は、システム全体の応答維持を優先し、完全なリアルタイム反映を求めない。画面には集計の最終更新日時を表示する（`01_admin_common_ui.md` §5）。
- 名刺入力画面・名刺情報照合は作業者が連続して操作する画面であり、1 件処理するごとの待ち時間が作業効率に直結する。次データの表示は他画面より短い目標を置く。

## 3. 可用性

- 目標稼働率は 99.5% 以上とする（計画メンテナンス時間を除く）。
- 計画メンテナンスは、名刺データ化作業の稼働時間帯を避けて実施する。実施時間帯は運用開始前に確定する。
- 障害発生時の目標復旧時間（RTO）と目標復旧時点（RPO）は確定前とする（※要確定・§8）。

## 4. セキュリティ

### 4.1 通信・保存

- 全通信を SSL/TLS で暗号化する。
- パスワードはハッシュ化（Bcrypt）して保存する。平文での保存・出力・ログ記録は行わない。
- 名刺画像および回答データは、アクセス権を持つアカウントからのみ取得できる状態とする。

### 4.2 アクセス制御

- 管理者画面には IP アドレス制限を適用する。許可対象の IP アドレス範囲は運用開始前に確定する。
- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- 直接 URL アクセス、API の直接呼び出しのいずれにおいても、対象データの所属グループを検証する。

### 4.3 実装上の対策

- SQL インジェクション、XSS への対策を実施する。
- 不正アクセスの検知のため、アクセスログを取得し監視する。
- サーバーへの Root ログインを禁止し、SSH は公開鍵認証とする。
- 不要なポートとサービスを無効化する。
- 脆弱性情報を定期的に確認し、パッチを適用する。

### 4.4 操作の追跡

顧客データ・金銭・アカウント権限に影響する操作は監査ログへ記録する。記録対象と記録項目は `02_admin_common_audit_log.md` に従う。

## 5. 運用・保守

- サーバーリソースとエラーログを監視する体制を置く。
- データは定期的にバックアップする。取得間隔と保持世代数は運用開始前に確定する。
- 障害発生時の連絡体制と対応フローを定める（体制と連絡先は※要確定・§8）。
- ソースコードはバージョン管理下に置く。

## 6. 対応環境

### 6.1 ブラウザ

- 対応ブラウザは Chrome / Firefox / Edge / Safari の最新版とする。
- IE および非 Evergreen ブラウザは対象外とする。

### 6.2 画面幅

- 管理者画面は PC での利用を前提とする。横幅 1024px 以上で全機能を利用できる状態とする。
- タブレットでは一覧・詳細の閲覧ができる状態を維持する。表形式の一覧は横スクロールでの表示を許容する。
- 名刺入力画面・名刺情報照合は PC での利用に限定する。

### 6.3 操作性

- 名刺入力画面・名刺情報照合は、キーボードのみで一連の作業を完結できるようにする。マウス操作も併用できる。
- 全画面で、主要な操作要素にキーボードでアクセスできるようにする。
- 入力欄はラベルと関連付ける。

## 7. データ量の前提

- 1 アンケートあたりの名刺件数、同時に稼働するアンケート数、オペレーターの同時接続数は確定前とする（※要確定・§8）。
- 一覧・検索・集計は、件数の増加に対してページングで対応する。取得方式（サーバー側で絞り込むか画面側で絞り込むか）は `01_admin_common_ui.md` §12 の #1 で確定する。

## 8. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | RTO / RPO | 障害発生時の目標復旧時間と目標復旧時点の数値を確定する。 |
| 2 | IP アドレス制限の範囲 | 管理者画面へアクセスできる IP アドレス範囲と、外部オペレーターの在宅作業を許容するかを確定する。 |
| 3 | 想定データ量 | 1 アンケートあたりの最大名刺件数、同時稼働アンケート数、オペレーターの同時接続数を確定する。性能目標の検証条件として用いる。 |
| 4 | 基準画面幅 | 管理者画面の基準幅を 1024px とするか 1280px とするかを確定する。一覧の列数が多い画面での見え方を基準に判断する。 |
| 5 | バックアップ方針 | バックアップの取得間隔、保持世代数、復元手順を確定する。 |
| 6 | 計画メンテナンス時間帯 | 名刺データ化作業の稼働時間帯を踏まえ、メンテナンス実施可能な時間帯を確定する。 |
| 7 | 名刺画像の保管期間 | 名刺画像および回答データをどこまで遡って保持するかを確定する。削除依頼への対応方針と併せて決める。 |
| 8 | 監視対象と通知先 | 監視するメトリクス、閾値、アラートの通知先を確定する。 |
| 9 | ダウンロードの性能目標 | CSV・名刺画像のダウンロードについて、データ量ごとの許容時間と処理中表示へ切り替える閾値を確定する。§2 の「10 秒」を正式値とするかを含めて決める。 |
| 10 | 障害時の連絡体制 | 障害発生時の一次連絡先、エスカレーション経路、対応時間帯を確定する。§5 の対応フローの前提となる。 |
