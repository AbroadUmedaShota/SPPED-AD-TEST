## 1. 文書目的

- 本書は、アンケート詳細の要件を定義する。本画面は独立した画面として新設する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- アンケートの横断検索と一覧は本書の対象外とし、`13_admin_survey_management.md` で扱う。

## 2. 画面概要

- アンケート 1 件に対する深い介入を集約する画面。
- 全設定の確認と変更、利用者側で制限されている操作の代行、公開後の変更を扱う。
- 影響の大きい操作は通常の編集と領域を分け、確認ダイアログと監査ログの記録を必須とする。
- 名刺データ化の申込プランを確認し、データ化の状態を把握する。

### 2.1 通常編集と危険操作の分離

| 区分 | 対象 | 扱い |
| --- | --- | --- |
| 通常編集 | 会期前の設定変更 | 保存操作で確定する |
| 危険操作 | 公開後のアンケート変更、個別回答の削除、強制停止、完了データの手動アップロード | 独立した領域に配置し、操作ごとの専用の確認画面で理由の入力を必須とし、監査ログの記録を伴う |

会期の状態によって、同じ項目でも扱う区分が変わる。会期状態別の操作可否を次のとおりとする。表の全体は確定前とする（※要確定・§11 の #10）。

| 会期状態 | タイトル・会期の変更 | 設問構成の変更 | 設定・状態・回答の確認 | 扱う区分 |
| --- | --- | --- | --- | --- |
| 会期前 | 可 | 可 | 可 | 通常編集。保存操作で確定する |
| 会期開始後〜会期終了 | 可 | 可 | 可 | 危険操作。独立した領域に配置し、確認ダイアログと監査ログの記録を伴う（§4.6） |
| 会期終了後 | 不可 | 不可 | 可 | 確認のみ |

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 運営全体を管理する Lv3・Lv4。顧客からの依頼に応じて設定を代行変更し、公開後の修正に対応する。

### 3.2 対象範囲

- アンケートの全設定の確認・設定・変更
- 利用者側で制限されている操作の代行実行
- 公開後のアンケート変更
- 強制停止と完了データの手動アップロード
- データ化申込プランの確認
- 顧客への確認依頼メールの送信

### 3.3 対象外

- アンケートの横断検索・一覧・作成・削除（`13_admin_survey_management.md`）
- 名刺データの入力・照合作業（`19_admin_data_input_list.md`、`21_admin_matching_list.md`）
- 請求金額と入金状態の操作（`15_admin_billing.md`）
- 利用者向けのアンケート作成画面の要件（`docs/リライト版仕様書/user/` で扱う）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくず、フッターを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルに対象のアンケートを識別できる情報（アンケート ID、タイトル）を表示する。
- 画面は上から、基本情報、設問構成、名刺データ化設定、回答状況、危険操作、操作ログの順に配置する。
- アンケート管理（SCR-A-004）へ戻る導線を配置する。

### 4.2 基本情報

次を表示し、運営側で変更できる。

| 項目 | 表示 | 変更 |
| --- | --- | --- |
| アンケート ID | 可 | 不可 |
| タイトル | 可 | 可 |
| 会期（開始日時・終了日時） | 可 | 可 |
| 作成者（ユーザー ID・氏名・会社名） | 可 | 不可 |
| 作業ステータス | 可 | 不可 |
| 作成日時・最終更新日時 | 可 | 不可 |

- 変更は保存操作で確定する。保存前に画面を離れる場合は確認ダイアログを表示する（`01_admin_common_ui.md` §8）。
- 変更内容は監査ログの記録対象（代行変更）とする（`02_admin_common_audit_log.md` §3）。

### 4.3 設問構成

- アンケートの設問構成を一覧で表示する。設問ごとに設問文、設問タイプ、必須の有無を表示する。
- 会期前は設問構成を変更できる。
- 会期開始後から会期終了までの設問構成の変更は §4.6 の危険操作として扱う。会期終了後は変更できない（§2.1）。
- 設問の編集機能は、利用者側のアンケート編集画面（アンケート作成機能）と同一の機能構成とする。設問タイプの選択、選択肢の編集、設問の追加・削除・並び替えを含む。運営側との相違点は、危険操作のゲート（確認ダイアログと監査ログの記録）を経由する点とする（※要確定・§11 の #5）。
- 設問の編集を本画面内で行うか、専用の画面へ分離するかは §11 の #5 で確定する。

### 4.4 名刺データ化設定

- 名刺データ化の申込プランと納期区分を表示する。
- データ化対象の名刺件数、入力・照合の進捗を表示する。
- 照合管理一覧（SCR-A-011 / SCR-A-012）へ遷移する導線を配置する。
- 本画面での操作は確認に限る。データ化作業そのものは作業画面で行う。

### 4.5 回答状況とお礼メール

- 受け付けた回答の件数と、直近の回答日時を表示する。
- 回答を一覧で確認できる。回答ごとに回答日時と名刺画像の有無を表示する。
- アンケートに設定されたお礼メールの内容を確認できる。
- 回答数の集計範囲（テスト回答を含むか）は §11 で確定する。

### 4.6 公開後のアンケート変更

会期開始後から会期終了までの間にアンケートの内容を変更する操作を、独立した領域に配置する。

- 対象は設問構成の変更と会期の変更とする。
- 会期終了後は本領域の操作要素を表示しない（§2.1、§7.2）。
- 実行前に専用の確認画面を表示し、対象のアンケート ID、変更する範囲（基本設定・設問構成・お礼メール設定から選択）、既存回答への影響を明示する。
- 実行には理由の入力を必須とし、監査ログの記録対象（公開後の設問変更）とする（`02_admin_common_audit_log.md` §3）。
- 既に受け付けた回答と変更後の設問構成の対応関係は §11 で確定する。

### 4.7 制限操作の代行実行

- 利用者側で制限されている操作を運営権限で実行する。会期中の設定変更がこれに該当する。
- 実行時は確認ダイアログを表示し、対象と操作内容を明示する。
- 実行は監査ログの記録対象（代行変更）とする。

### 4.8 確認依頼メールの送信

- アンケートの内容について、顧客へ確認を依頼するメールを送信する。
- 送信前に宛先と送信内容を画面上で確認する。
- 宛先の特定条件は `03_admin_common_notifications.md` §8 の #1 で確定する。

### 4.9 操作ログ

- 対象のアンケートに対して行われた運営側の操作を、時系列で表示する。
- 表示するのは監査ログの記録対象のうち、当該アンケートを対象とする操作とする（`02_admin_common_audit_log.md` §3）。
- 横断ログと本画面の個別ログは同一のデータを参照する。

### 4.10 追加要件（あったほうが良い）

| 要件 | 内容 |
| --- | --- |
| 個別回答の削除 | 回答者からの削除依頼に対応するため、回答を 1 件単位で削除する |

- 個別回答の削除は、回答 ID の指定で対象を特定し、削除前に対象のプレビュー（回答日時、名刺の氏名・会社、データ化の状態）を表示する。
- 実行には理由の入力を必須とし、削除した回答は復元できない旨を確認画面に明示する。
- 削除依頼への対応では、回答本体に加えて名刺画像と過去に蓄積したデータへの波及が発生する。波及範囲は §11 で確定する。

### 4.11 強制停止

- トラブル発生時に、会期中のアンケートの回答受付を即時停止する。危険操作の領域に配置する。
- 実行前に専用の確認画面を表示し、再開には管理者の操作が必要である旨を明示する。実行には理由の入力を必須とする。
- 実行は監査ログの記録対象とする。停止時の詳細な挙動は `13_admin_survey_management.md` §11 の #7 で確定する。

### 4.12 完了データの手動アップロード

- 通常の照合フローが機能しない場合に、完成データのファイル（CSV）を直接取り込む。危険操作の領域に配置する。
- 取込前に、取込モード（全件置換・差分追記のいずれか。既定と許可範囲は※要確定）を選択し、取込プレビュー（検出件数、ヘッダーの整合、重複の有無）を表示する。
- 実行には理由の入力を必須とし、監査ログの記録対象とする。
- 通常は照合の完了によって完成データが反映されるため、本操作は障害時の代替手段（非常口）として位置づける。適用条件は `13_admin_survey_management.md` §11 の #6 で確定する。

## 5. 通知

本画面の操作を起点として次の通知が発火する（`03_admin_common_notifications.md` §2）。

| 契機 | 通知 | 宛先 |
| --- | --- | --- |
| 確認依頼を送信したとき | 確認依頼メール | 対象アンケートの利用者 |

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない |
| Lv2 | 本画面へアクセスできない |
| Lv3 | 全範囲のアンケートを表示・操作できる |
| Lv4 | 全範囲のアンケートを表示・操作できる |

- 本画面は顧客情報を扱うため、Lv2 以下はテナント分離により到達しない（`00_admin_common_permissions.md` §3）。
- 権限判定はサーバー側で行う（`00_admin_common_permissions.md` §9.1）。
- 危険操作（公開後の変更・個別回答の削除・強制停止・完了データの手動アップロード）を実行できる権限レベルは §11 で確定する。

## 7. 状態と挙動

### 7.1 初期表示

- アンケート管理から遷移した対象のアンケートの情報を表示する。
- 各入力欄には現在の値を表示する。

### 7.2 会期による操作の可否

- 会期状態別の操作可否は §2.1 の表に従う。
- 会期前は基本情報と設問構成を通常編集として変更する。
- 会期開始後から会期終了までは、タイトル・会期・設問構成の変更を危険操作として扱い、確認ダイアログと監査ログの記録を伴う（§4.6、§4.7）。
- 会期終了後は、設定・データ化の状態・回答の確認に限る。
- 会期の状態によって実行できない操作は、操作要素を表示しない。

### 7.3 保存

- 保存操作で変更内容を確定する。保存中はボタンを非活性化し、二重実行を防ぐ（`01_admin_common_ui.md` §7.3）。
- 保存に成功した場合は画面上部に成功メッセージを表示する。
- 保存に失敗した場合は入力内容を保持し、失敗した旨を表示する。

### 7.4 操作の記録

次の操作は監査ログに記録する（`02_admin_common_audit_log.md` §3）。

- 設定の代行変更
- 公開後の設問変更
- 個別回答の削除
- 強制停止
- 完了データの手動アップロード

## 8. 現行画面からの引き継ぎ

現行のアンケート管理では、一覧行の「編集」を押下しても同一画面へ戻り、詳細画面が存在しない。本画面は新設として全機能を新たに実装する。

参考: 現行モック `03_admin/survey-detail.html` は本書の内容と同期している（基本設定・状態と数値・危険操作 4 種の専用確認画面・個別操作ログ）。

## 10. 画面確認観点

モックアップ上で次を確認する。

- [ ] アンケート管理から対象を選択して本画面へ遷移できる
- [ ] 画面タイトルに対象のアンケート ID とタイトルが表示される
- [ ] 基本情報が表示され、タイトルと会期を変更して保存できる
- [ ] 設問構成が設問文・設問タイプ・必須の有無とともに一覧表示される
- [ ] 会期開始後の設問構成の変更が、通常編集と別の領域に配置される
- [ ] 公開後の変更の実行前に専用の確認画面が表示され、変更する範囲の選択と既存回答への影響が明示される
- [ ] 危険操作の 4 操作（公開後の変更・個別回答の削除・強制停止・完了データの手動アップロード）それぞれに専用の確認画面があり、理由の入力が必須である
- [ ] 個別回答の削除で、回答 ID の指定と対象のプレビューが表示される
- [ ] 完了データの手動アップロードで、取込モードの選択と取込プレビューが表示される
- [ ] データ化申込プランと納期区分が表示される
- [ ] 照合管理一覧への遷移導線が表示される
- [ ] 回答件数と回答一覧が表示される
- [ ] お礼メールの内容を確認できる
- [ ] 確認依頼メールの送信前に、宛先と送信内容を画面上で確認できる
- [ ] 操作ログに、当該アンケートに対する代行変更と危険操作が表示される
- [ ] Lv2 以下でログインした場合、本画面の URL へ直接アクセスしても表示されない

## 11. 画面外の確認事項

| # | 項目 | 内容 |
| --- | --- | --- |
| 1 | 公開後フォーム変更の方式 | 会期開始後に設問構成を変更する方式を確定する。設問を追加のみ許可するか、既存設問の変更・削除まで許可するかを決める。 |
| 2 | 既存回答との対応関係 | 公開後に設問を変更した場合、変更前に受け付けた回答をどう表示・出力するかを確定する。 |
| 3 | 回答の修正・削除権限 | 個別回答の修正と削除を実行できる権限レベルを確定する。Lv4 限定とするかを含めて決める。 |
| 4 | 削除依頼対応の波及範囲 | 回答を削除した際に、名刺画像と過去に蓄積したデータへどこまで波及削除するかを確定する。過去データの実体は開発側へ確認を要する。 |
| 5 | 設問編集の配置と機能構成 | 設問の編集を本画面内で行うか、専用の画面へ分離するかを確定する。設問数が多い場合の操作性を基準に判断する。あわせて §4.3 の編集 UI の機能構成について、利用者側のアンケート編集画面と同一でよいか、運営側だけに必要な操作（回答済み設問の扱いなど）を追加するかを確定する。 |
| 6 | 回答数の集計範囲 | 回答件数にテスト回答を含めるかを確定する。アンケート管理の一覧表示と定義を揃える。 |
| 7 | 確認依頼メールの宛先 | アンケート作成者とするか、契約上の連絡先とするかを確定する。 |
| 8 | 会期変更の制約 | 会期の開始日時・終了日時を変更できる範囲を確定する。会期後への延長、開始日時の遡及変更の可否を決める。 |
| 9 | データ化設定の変更可否 | 名刺データ化の申込プランを運営側で変更できるようにするかを確定する。変更する場合、請求への影響を決める。 |
| 10 | 会期状態別の操作可否 | §2.1 の表を正式な要件として確定する。会期終了後にタイトル・会期・設問構成の変更を一切認めない扱いでよいか、認める場合の権限レベルと記録方法を決める。#8 の会期変更の制約と同時に確定する。 |
