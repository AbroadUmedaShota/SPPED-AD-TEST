# 営業日カレンダー 要件定義書

| 項目 | 値 |
| --- | --- |
| 対象画面 | `/admin/calendar` |
| 画面 ID | SCR-A-008 |

## 1. 文書目的

- 本書は、営業日カレンダーの要件を定義する。
- 全画面に共通する権限、UI 規則、監査ログ、通知、用語は共通編を参照する。本書は本画面に固有の要件を扱う。
- 納期日時そのものの表示と照合作業の進捗は本書の対象外とし、`21_admin_matching_list.md` で扱う。

## 2. 画面概要

- 納期計算の前提となる休業日と振替営業日を運営側で管理する画面。
- あわせて、Lv2 が案件量と人員を見比べて作業をアサインする運用画面として機能する。
- 月単位のカレンダーを中心に構成し、日付ごとの営業日設定、その日に会期を持つアンケート、作業のアサイン状況を扱う。
- 表示範囲と操作範囲はログイン中アカウントのデータ範囲と権限に従う（§6）。

### 2.1 アサインの責務分担

| 画面 | 担当する範囲 |
| --- | --- |
| 営業日カレンダー（本画面） | アサインの実行。アンケートと会社の組み合わせで投入人数を決め、案件量と処理能力の過不足を判断する |
| データ入力対象一覧（SCR-A-009） | 作業の実施。作業可能件数の確認と入力画面への遷移 |

アサイン結果をデータ入力対象一覧へどう反映するかは §7.3 で扱う。

## 3. 想定利用者と対象範囲

### 3.1 想定利用者

- 作業をアサインする Lv2（OperatorAdmin）。案件量と人員のバランスを見て、日ごとの作業割当を決める。
- 営業日を管理する Lv3・Lv4。休業日・振替営業日を設定し、納期計算の前提を維持する。

### 3.2 対象範囲

- 休業日・振替営業日の設定と変更
- 定休日（曜日単位）の設定
- 月次カレンダー上でのアンケート表示
- 作業のアサインとキャパシティの調整

### 3.3 対象外

- 納期日時の算出ロジック
- 入力・照合の作業進捗（`19_admin_data_input_list.md`、`21_admin_matching_list.md`）
- オペレーターの登録・権限設定（`23_admin_operator_management.md`）

## 4. 画面要件

### 4.1 共通構成

- ヘッダー、サイドバー、パンくずを表示する（`01_admin_common_ui.md` §2）。
- 画面タイトルを表示する。
- カレンダーを中心に配置し、前月・翌月へ移動する操作を用意する。
- 表示モードを 3 つ持ち、切り替えられるようにする（2026-08-12 追加）。

| モード | 表示範囲 |
| --- | --- |
| 単月 | 対象月の週のみを表示する |
| 前後2週（既定） | 対象月の前 2 週から後 2 週までを上下に並べて表示する。月が替わる位置に月名の区切り行を挟み、対象月以外の日付は淡色で示す |
| 年間 | 月×指標の一覧表（§4.2.1）。日別のカレンダーは表示しない |

- 月セルには会期と作業期間を帯で並べ、下部にその日の必要枚数と供給枚数を併記する。帯と枚数の表示切り替えは設けない。両方を同時に読めるため、切り替える利点がないためである。

### 4.2 カレンダー表示

- 1 日を 1 マスとして日付順に配置する。表示範囲は §4.1 の表示モードに従う。
- 各日付には次を表示する。

| 表示項目 | 内容 |
| --- | --- |
| 日付 | 年月日 |
| 営業日区分 | 営業日、休業日、振替営業日のいずれか |
| 会期の帯 | その日に会期を持つアンケート（名刺が集まる期間） |
| 作業期間の帯 | その日にデータ化作業があるアンケートと、その充足状態 |
| 必要枚数・供給枚数 | その日に作業がある案件を通した 1 日あたりの合計 |
| 不足案件数 | その日に作業がある案件のうち供給が必要量に届いていない件数 |

- 枚数・人数は数値で表示する。図やグラフは用いない。
- 日付を選択すると、カレンダー下部の日付詳細領域に、その日の対象アンケートとアサイン状況を表示する（§4.4、§4.5）。
- 選択中の日付は、営業日区分の表示とは別に、選択状態としてカレンダー上で識別できるようにする。
- カレンダーには、休業日・振替営業日・選択中の各状態を示す凡例を添える。
- 月セルの表示方式は §4.4 で確定する。

#### 4.2.1 年間ビュー（2026-08-12 追加）

- 年間モードでは、月×指標の一覧表を表示する。図やグラフは用いない。
- 各月の行に、営業日数・休業/振替の個別設定数・会期のあるアンケート件数・予定枚数合計・不足日数・要員重複日数を表示する。
- 予定枚数合計は会期初日の属する月に計上し、月をまたいで二重に数えない。不足日数は、その日に必要枚数へ届かない案件がある日の数とする。
- 月の行を選択すると、前後2週モードでその月を表示する。
- 年間モードでは日付単位の道具（絞り込み・月次集計行・日付詳細領域）は表示しない。

### 4.3 営業日の設定

| 設定 | 内容 |
| --- | --- |
| 定休日 | 曜日単位で休業日とする設定。土曜・日曜・祝日をそれぞれ指定する |
| 個別休業日 | 日付を指定して休業日とする設定 |
| 振替営業日 | 定休日にあたる日付を、営業日として扱う設定 |

- 設定の変更は Lv3 以上が行う（§6）。
- 個別休業日と振替営業日には、設定の理由をメモとして記録できる。
- 設定を削除する場合は確認ダイアログを表示する（`01_admin_common_ui.md` §7.1）。

同一の日付に複数の設定が及ぶ場合、次の規則で解決する。規則の全体は確定前とする（※要確定・§11 の #12）。

- 個別設定（個別休業日・振替営業日）を定休日・祝日より優先する。定休日・祝日と重なる日付では、個別設定の内容をカレンダー表示と納期計算に用いる。
- 同一の日付に個別休業日と振替営業日を重複して設定することはできない。重複する設定を保存しようとした場合はエラーを表示し、保存しない。

### 4.4 アンケート表示

- 月セルには、アンケートを **帯** として表示する。帯は会期の初日から納期までを横につなぎ、週をまたぐ場合は継続を示す記号を端に置く。
- 帯は次の 2 区間で構成する。1 案件の 2 区間は同じ段に並べる。

| 区間 | 範囲 | 表示 |
| --- | --- | --- |
| 会期 | 会期の初日から最終日 | 名刺が集まる期間。情報として示し、充足の色は付けない |
| 作業期間 | §4.5.1 で算出する作業日の初日から納期 | データ化を行う期間。充足状態の色はこちらに付ける |

- 納期区分がオンデマンドの案件は会期中にデータ化するため、会期と作業期間が一致する。この場合の帯は 1 区間とする。
- 1 週に並べる帯には上限を設け、あふれた件数は月セルの下部に「他 N 件」として示す。
- 月セルの下部には、その日に作業がある案件を通した必要枚数と供給枚数の合計、および不足している案件の件数を表示する。会期のみで作業のない日は表示しない。
- 日付または帯を選択すると、日付詳細領域にその日のアンケートとアサイン状況を表示する。アンケートごとにアンケート ID、タイトル、会期、納期区分、納期、作業期間を表示する。
- 日付詳細領域に収まらない件数がある場合は、領域内の縦スクロールで全件を確認できるようにする。
- 表示対象はログイン中アカウントのデータ範囲に限定する。

日付詳細領域のアンケートごとに、作業画面への遷移導線を配置する。

| 遷移先 | 表示条件 | 引き継ぐ内容 |
| --- | --- | --- |
| データ入力対象一覧（SCR-A-009） | 対象アンケートに名刺データ化の対象が存在する場合に表示する | 選択中の日付と対象アンケート |
| 照合結果一覧（SCR-A-011 / SCR-A-012） | 対象アンケートに名刺データ化の対象が存在する場合に表示する | 選択中の日付と対象アンケート |

- 引き継いだ日付とアンケートは、遷移先の絞り込み条件へ適用した状態で表示する。

### 4.5 アサイン

- アンケートと会社の組み合わせで、投入する人数をアサインする。誰を出すかは各社が社内で決めるため、本画面では会社と人数までを扱い、個人は指定しない。
- 人数は会期の全日ではなく、§4.5.1 の作業期間を通した 1 日あたりの人数とする。
- アサインを確定すると、担当会社のオペレーター管理者（Lv2）へ割当通知を送信する（§5）。
- 人数を 0 にすることでアサインを取り消せる。

#### 4.5.1 作業期間と必要人員の算出

作業期間は納期区分から算出する。納期の起算は会期終了日の翌営業日を 1 営業日目とし、営業日の判定には §4.3 の営業日設定（定休日・個別休業日・振替営業日）を用いる。休業日を追加すると納期と作業期間が後ろへずれる。

| 納期区分 | 納期 | 作業期間 |
| --- | --- | --- |
| オンデマンド | 当日中 | 会期の各日 |
| 超特急 | 1 営業日 | 会期終了日の翌営業日から 1 営業日 |
| 特急 | 3 営業日 | 会期終了日の翌営業日から 3 営業日 |
| 通常 | 6 営業日 | 会期終了日の翌営業日から 6 営業日 |
| お試し | 6 営業日 | 会期終了日の翌営業日から 6 営業日 |

納期区分ごとの営業日数と起算の規則は利用者側の定義と一致させる（`04_admin_common_glossary.md` §4）。

充足の判定は人数ではなく処理枚数で行う。会社ごとに 1 人 1 日あたりの処理枚数が異なるため、同じ人数でも処理できる量が変わるためである。

```text
1 日あたり必要枚数 = 見込み枚数 ÷ 作業期間の営業日数
1 日あたり供給枚数 = Σ 会社ごと（投入人数 × その会社の 1 人 1 日あたり処理枚数）
充足率              = 供給枚数 ÷ 必要枚数
```

充足率で次の段階に分けて表示する（2026-08-12 追加）。安全バッファは持たず素の 100% で判定する。段階の閾値は暫定値とし、実画面のレビューで調整する（※要確定・§11 の #16）。

| 状態 | 条件 |
| --- | --- |
| 未アサイン | 供給枚数が 0 |
| 不足（深刻） | 充足率 70% 未満。このままでは処理できない水準 |
| 不足 | 充足率 70% 以上 100% 未満 |
| 充足 | 充足率 100% 以上 130% 以下 |
| 人数過多 | 充足率 130% 超。余剰の枚数と平均換算の人数を示し、他案件へ回せることを伝える |

- 見込み枚数は利用者側の名刺データ化設定で入力された想定件数を用いる（アンケート回答 1 件＝名刺 1 枚）。
- 人数は平均的な生産性から換算した目安として併記する。人数が目安に達していても担当会社の処理能力では届かない場合があるため、その旨を示す。
- 日単位の不足は、案件ごとの不足分の合計で数える。会社が異なれば供給を融通できないため、その日の合計が足りていても案件単位では不足しうる。

#### 4.5.2 会社ごとの処理能力

処理能力は「1 人あたりどれだけ処理できるか」と「何人出せるか」の 2 つに分け、取得元を変える。

| 要素 | 取得元 | 理由 |
| --- | --- | --- |
| 1 人 1 日あたりの処理枚数 | オペレーター実績確認（SCR-A-015）の当月の作業件数 ÷ 当月の営業日数 ÷ 対象人数 | 生産性は過去の実測から推定する |
| 同時に出せる人数の上限 | オペレーター管理（SCR-A-014）で状態が有効なアカウント数 | 実績から人数を導くと、退職・無効化された人の過去実績を現在の戦力として数えてしまう |

無効・招待中のアカウントは稼働可能な人数に数えない。稼働可能なアカウントが 0 名の会社へは人数を入力できないようにし、増員依頼の宛先としても既定では選択しない。

同じ人員を複数の案件へ重複して配員できないようにする。上限は案件ごとではなく、作業日をまたいで判定する。

```text
その案件が確保できる人数 = 稼働可能なアカウント数 − 作業日が重なる他案件での使用人数の最大値
```

作業日のうち他案件の使用が最も多い日を基準とする。入力欄はこの人数を上限とし、確定時にも同じ上限で頭打ちにする。上限を差し引いた理由（どの程度が他案件で使用中か）を画面上に示す。

営業日設定を変更すると作業日がずれるため、配員した時点では上限内だった案件どうしが後から同じ日に重なることがある。営業日の変更は正当な操作なので中止させず、重複を見逃せないようにする。

- 重複が発生している日は、月セルにその旨を示す。月セルは 1 行で溢れを切り落とすため、警告は行の先頭に置き、幅が狭い環境でも消えないようにする。切り落とされた内容は補足表示から読めるようにする。
- 重複が発生している日数を月の集計に表示する。どの日かは補足表示で確認できるようにする。
- 営業日設定の変更によって重複が発生した日があるときは、変更の直後に対象の日付を挙げて通知する。判定は重複日数の増減ではなく**日付の集合の差分**で行う。日数が同じまま別の日へ移った場合を見逃さないためである。
- 重複の解消は配員の見直しで行う。設定変更を理由に配員を自動で減らさない。

実績は「その会社に振られた量」であって処理能力の上限とは限らない。稼働率の低い会社は実力より小さく出るため、推定値であることを明示したうえで会社ごとに上書きできるようにする。上書きは Lv3 以上が行う。

必要枚数が全社を総動員した処理枚数を超える案件は、増員では解決しない。人員不足とは区別して示し、納期区分または受注量の見直しが必要であることを伝える。

#### 4.5.3 増員の依頼

不足している案件について、Lv3 以上が各社のオペレーター管理者（Lv2）へ増員を依頼できる。依頼には対象アンケート、会期、納期区分、納期、作業期間、必要枚数、供給枚数、不足枚数を含める。送信すると対象案件を追加募集中とする。

募集状態は充足状態から自動で遷移させ、運営の手作業を要しない（`01_admin_common_ui.md` §7.4・2026-08-12 追加）。

- 不足（供給枚数 < 必要枚数）の案件は自動で「追加募集中」、充足した案件は自動で「募集完了」とする。
- 手動の締切・再開は例外操作として残す。不足を承知で打ち切った締切は運営の意思決定として維持する。充足時に付いた締切が営業日変更などで後から不足へ戻った場合は、自動判定（追加募集中）へ戻す。

## 5. 通知

- アサインを確定したとき、担当会社のオペレーター管理者（Lv2）へ割当通知を送信する（`03_admin_common_notifications.md` §2 の #5）。
- 不足している案件について増員を依頼したとき、宛先に指定した会社のオペレーター管理者（Lv2）へ通知を送信する（§4.5.3）。
- 通知には対象の日付と作業内容を含める。
- 同一オペレーターへの複数のアサインが同時に確定した場合の送信単位は `03_admin_common_notifications.md` §8 の #2 で確定する。

## 6. 権限とデータ範囲

| 権限レベル | 扱い |
| --- | --- |
| Lv1 | 本画面へアクセスできない。サイドバーに項目を表示しない |
| Lv2 | 自グループのデータのみを表示・操作できる。操作はキャパシティ調整と作業アサインに限る |
| Lv3 | 全グループのデータを表示・操作できる。休業日・振替営業日の設定を含む全機能を利用できる |
| Lv4 | 全グループのデータを表示・操作できる。休業日・振替営業日の設定を含む全機能を利用できる |

- Lv2 に対しては、営業日設定の操作要素を表示しない（`00_admin_common_permissions.md` §6）。
- Lv2 は営業日設定の内容を参照できる。納期の前提となる休業日を把握したうえでアサインを判断するための規定であり、たたき台に対応する記載はない（※要確定・§11）。
- 権限判定とデータ範囲の絞り込みはサーバー側で行う（`00_admin_common_permissions.md` §9.1）。

## 7. 状態と挙動

### 7.1 初期表示

- 当月のカレンダーを表示する。

### 7.2 営業日設定の反映

- 営業日設定を変更すると、以降に算出する納期日時へ反映する。
- 既存案件の納期日時へ遡って反映するかは §11 で確定する。

### 7.3 アサインの反映

- アサインを確定すると、対象案件の供給枚数と、作業期間に含まれる各日の集計を更新する。
- アサイン結果をデータ入力対象一覧（SCR-A-009）へどう反映するかは §11 で確定する。出題対象そのものを制約するか、進捗把握のための記録に留めるかで、作業者側の挙動が変わる。

### 7.4 集計値の反映

- 見込み枚数と、処理能力の推定に用いるオペレーター実績は、最大 5 分の反映遅延を許容する（`05_admin_nonfunctional.md` §2）。

## 8. 現行画面からの引き継ぎ

現行画面 `/admin/calendar` は次を備える。本画面はこれらの機能を引き継ぐ最低線とする。

| 現行の機能 | 本書での扱い |
| --- | --- |
| 定休日設定（土曜・日曜・祝日のチェック） | §4.3 |
| 個別休業日の設定 | §4.3 |

振替営業日の設定、アンケート表示、アサインは現行画面に存在しない。§4.3〜§4.5 は新規に追加する要件として扱う。

参考: 現行モック `03_admin/calendar-management.html` は 2026 年 6〜8 月の 3 か月を対象に、月移動、日付選択と日付詳細、アサインの追加・取り消し、個別休業日・振替営業日の追加（重複と振替妥当性の検証込み）と削除確認、定休日・祝日の設定、CSV インポート（§4.6）をページ内の状態で実装している。会期はアンケート管理と同一のものを用い、納期は §4.5.1 の規則から算出する。モックは仕様上の正解とは扱わない。
